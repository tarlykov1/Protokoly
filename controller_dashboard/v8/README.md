# Кабинет контролёра v8.0

Поставка для gsprom-app113 и узла портала Битрикс24. Исходная ветка feature/controller-dashboard, базовый пилот v7.1. В существующем портале кабинет открывается внутри Битрикса по /controller/. Базовый установщик для чистого контура использует /controller-v8/. Действующие main.py, bitrix-dashboards, r10, пилот и базы пилота установщик не редактирует.

## Обновление существующего /controller/

На веб-узле распакуйте ZIP в новый временный каталог. Из каталога controller-v8 выполните `sha256sum -c SHA256SUMS`, затем от root запустите `bash update-portal.sh`. Установщик проверяет наличие установленной страницы и сохраняет резервную копию и команду отката. Для этой редакции достаточно обновления портала, работающий сервис на gsprom-app113 совместим. При использовании SSH-туннеля он должен быть доступен веб-узлу.

## Установка

1. Распакуйте один и тот же ZIP на обоих узлах. В каталоге controller-v8 выполните `sha256sum -c SHA256SUMS`.
2. На gsprom-app113 используйте интерпретатор существующей службы с fastapi, uvicorn и доступом к /webapp/app. Проверьте, что пользователь dev имеет доступ к кэшу МЕМО и рабочему каталогу protocol_dashboard. Выполните **от root** `V8_PYTHON=/абсолютный/путь/к/python bash install.sh backend`. Получится отдельная служба controller-v8 на 127.0.0.1:18108. При необходимости поставьте настройки среды интеграции protocol_dashboard в /etc/controller-v8/server.env. Сохраните строку V8_TOKEN. Для дальнейших изменений среды перезапускайте только controller-v8.
3. Без вывода токена в терминал создайте файл для передачи на веб-узел: `(umask 077; sed -n 's/^V8_TOKEN=//p' /etc/controller-v8/server.env > /etc/controller-v8/token)`. Доставьте его по защищённому каналу в /etc/controller-v8/token на портале. Дайте группе PHP-FPM право чтения файла и прохода по каталогу. Для удалённого портала используйте внутренний HTTPS reverse proxy к 127.0.0.1:18108 либо существующий защищённый туннель с loopback-адресом на стороне PHP. Не публикуйте сервис как маршрут браузера.
4. На портале скопируйте portal.example.php в /etc/controller-v8/portal.php. Сверьте группы с рабочей настройкой протоколов, добавьте все нужные группы. 734 – группа пилота, перечень в примере не описывает полный производственный охват. Настройте backend и исключения technical_ids (ID технических пользователей списка 91). Список 83 связывает поле «Исполнитель (Ответственный руководитель)» с одним или несколькими сотрудниками в поле «Помощник». При других названиях укажите manager_property и assistant_property. По умолчанию comments_source=null (auto): кабинет ищет однозначно связанный форум задачи или доступный текущему пользователю чат TASKS_TASK. При миграции и наличии двух связей указать проверенный источник forum или chat можно отдельно в настройках группы. При недоступном или неоднозначном источнике показатель остаётся неизвестным. В группе со смешанными источниками общий признак непрочитанного недоступен после обновления сводки.
5. На узле Битрикс24 выполните `bash install.sh portal /путь/к/document_root`. PHP должен иметь доступ к модулям tasks, socialnetwork, iblock и каталогу конфигурации. Повторная установка поверх существующего v8 останавливается. Откройте /controller-v8/ в действующей сессии Битрикс24.

## Данные и методика

- МЕМО: ID поручений из memo_activity_cache.json группы 671 (можно согласованно изменить V8_MEMO_GROUP и конфигурацию портала). Протоколы: штатный отчёт protocol_dashboard в режиме eos/assignments с пользователем и одной разрешённой группой. Готовый отчёт переиспользуется только в том же контексте. Время источника и время чтения актуальных полей задач показаны раздельно.
- Сначала проверяются роль по списку 91 и членство в группе; администратору доступны настроенные группы. В обеих ветках дополнительно проверяются права чтения каждой задачи через CTasks::GetList. Отметку чтения можно записать только для разрешённой задачи и выданного сервером номера комментария. Список 83 используется только для поиска помощников среди наблюдателей.
- Неактуальность определяется по обозначению отмены/неактуальности в статусе источника или стадии, а также по явно заданным ID obsolete_stages конкретной группы. Добавляйте ID из работающего канбана. При отсутствии подтверждённой стадии или классификации состояние неизвестно. В последнем цикле учитывается сдача или завершение главным ответственным или его помощником из списка 83. Переход в статус «Завершена» контролёром из списка 91 также засчитывается главному ответственному. Пометки различают закрытие контролёром и приёмку после сдачи. Закрытие без такого подтверждения имеет неизвестный результат.
- ИД = исполненные / (исполненные + открытые). «Закрыты в срок» = исполненные с фактическим закрытием не позже зафиксированного в задаче срока / все исполненные. При неизвестном результате или пропавшем источнике процент отсутствует. Сроки сравниваются по времени, без переноса на следующий рабочий день. Фильтры ограничивают реестр и KPI. Выбор зоны внимания ограничивает реестр внутри той же выборки.
- Срезы записываются после успешного обновления группы пользователем. Для одного московского дня хранится последнее наблюдение. График показывает последний совместный срез разрешённых групп за период в пределах текущего отбора. Исторический состав ограничен задачами, доступными пользователю сейчас. Группировка по людям использует сегодняшнего главного ответственного. Первая выгрузка даёт одну точку. График не строит ретроспективу по сегодняшнему статусу. Автоматического ночного сбора нет.
- Пятидневная неделя, Москва, 09–13 и 14–18 (в сокращённый день до 17). Календарь РФ 2018–2026 из xmlcalendar/data, ревизия 83d03f2cee2b0358c4aa8e04a728bdcc0cdb6e4c; праздничные, перенесённые и сокращённые дни включены. Для других лет календарные нормы неизвестны. Семь рабочих дней считаются по рабочим датам после дня последней активности. Источник календаря: https://github.com/xmlcalendar/data/tree/83d03f2cee2b0358c4aa8e04a728bdcc0cdb6e4c/ru
- История сроков берётся из журнала, назначение первого срока и снятие срока не считаются переносами. Реакция – опубликованный пользовательский комментарий от контролёра из 91. Просмотр фиксируется при открытии и загрузке карточки; до первого просмотра признак нового комментария неизвестен. Для отсутствующего руководителя и связи с оргструктурой кабинет показывает «Нет данных».
- SQLite в /var/lib/controller-v8 содержит дневные состояния и персональные отметки. Тексты задач, ФИО и комментарии в эту базу не записываются.

## Проверка и откат

На gsprom-app113 проверьте `systemctl status controller-v8` и ответ 403 на `curl -i -X POST -H 'Content-Type: application/json' -d '{}' http://127.0.0.1:18108/observe`. На портале проверьте отказ анонимному пользователю, отсутствие чужих групп и задач, вход контролёра из 91 и администратора. Сверьте по одной открытой, завершённой, возвращённой и неактуальной задаче с карточками Битрикс24. Откройте комментарии двумя пользователями и проверьте независимость прочтения. При остановке v8 агрегаты должны стать недоступны, действующие кабинеты должны открываться.

Откат портала: `bash rollback.sh portal /путь/к/document_root`. Откат gsprom-app113: `bash rollback.sh backend`. Служба v8 останавливается и отключается, настройки и история v8 сохраняются. Исходная v7.1 остаётся доступна по прежнему адресу.

## Сборка и проверки

Из controller_dashboard/v8 в репозитории: `python -m unittest discover -s tests`, `node --test tests/model.cjs`, `php tests/history.php`, `python build.py controller-v8.0.zip`. CI также проверяет синтаксис PHP, JavaScript, shell и контрольные суммы распакованной поставки.
