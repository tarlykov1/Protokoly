# Кабинет контролёра – единый реестр требований и приёмки
Дата фиксации: 27.10.2026. Основание: замечания Екатерины Карпенко по драфту, скриншоты писем и последующие уточнения владельца.

> Это **ТЗ и чек-лист**, а не заявление о реализации. Пока API отдаёт только МЕМО (группа 671). Протоколы отсутствуют. Не подменять календарные дни рабочими без производственного календаря и не считать комментарий новым без персональной отметки просмотра.

## 1. Реестр и фильтры
- [ ] Поиск по **исполнителям**, а не только по тексту поручения. Отдельный фильтр с поиском ФИО и поддержкой соисполнителей.
- [ ] В реестре отображать **главного ответственного, соисполнителей, помощника, руководителя**: отдельно «руководитель в задаче Битрикс24» и «руководитель по оргструктуре»; отсутствие данных показывать явно.
- [ ] Горизонтальный скролл реестра **сверху и снизу**, синхронный, с учётом изменения ширины таблицы/фильтров.
- [ ] Фильтры тип документа (МЕМО/протокол), группа, мероприятие, сроки, исполнитель, период; сохранять предсказуемые счётчики.
- [ ] Дата **последней успешной выгрузки** с датой и временем; не путать её со временем открытия страницы.

## 2. KPI и динамика
- [ ] ИД = число исполненных актуальных поручений / все актуальные поручения; **неактуальные исключены** из знаменателя и показаны отдельно. Задача с несколькими участниками считается исполненной при завершении главным ответственным.
- [ ] Вместо дублирующих KPI «Актуальные» и «Исполнено» показывать **«Доля закрытых поручений в срок»** с явно описанным знаменателем и методикой.
- [ ] **Линейная динамика** в стилистике действующего МЕМО, переключение недель/месяцев/кварталов/лет; не путать число закрытых задач с процентной динамикой.
- [ ] Отдельный блок **динамики по исполнителям**.

## 3. Зоны внимания
- [ ] «Просрочено» с разбивкой **по реальным стадиям канбана МЕМО**.
- [ ] «Ждёт контроля», «Срок сегодня», «Внесены изменения», «Нет активности более 7 рабочих дней», «Неоднократный перенос срока».
- [ ] Подсветка исполнителей, которые **не нажали «Начать выполнение» в течение 48 рабочих часов после постановки**; брать событие из истории, не выводить из одного текущего статуса.
- [ ] Отдельно доработать **«Требует внимания» в действующем дашборде активности МЕМО**, разбив по стадиям канбана, не ломая стабильный r10.

## 4. Комментарии и история
- [ ] **«Есть реакция контролёра»** = комментарий в задаче от пользователя из настроенного списка контролёров; нельзя считать любой комментарий. ID списка контролёров уточняется.
- [ ] **«Есть новый комментарий»** – отдельно от реакции контролёра; учитывать последний просмотр данной задачи **данным пользователем**, для чего требуется безопасный журнал per-user read-marker. До появления механизма показывать «не определено», а не false.
- [ ] История изменений сроков с количеством переносов и последовательностью дат; использовать журнал задач Битрикс24, не угадывать из текущего срока.

## 5. Источники, права и сроки
- [ ] Объединить **МЕМО + Протоколы** в единый реестр и показатели, получить протокольные поручения из `protocol_dashboard`/рабочего источника (не имитировать нулевой массив протоколов).
- [ ] Членство/полномочия проверять на **PHP-стороне Битрикс24**, проверять каждый доступный набор групп. Не выдавать общий кэш через публичный endpoint.
- [ ] Защищать Python backend общим серверным секретом, не помещать его в браузер, URL или Git. Администратор и отдельно назначенный контролёр могут иметь доступ по соответствующим правилам.
- [ ] Для норм «48 часов», «7 дней» использовать **рабочий календарь РФ**, исключающий выходные и официальные нерабочие праздничные дни с учётом переносов. Срок самой задачи не переносить автоматически.
- [ ] Показывать состояние источников и дату выгрузки каждого (МЕМО, протоколы); если источник недоступен, не обозначать суммарный показатель как полный.

## Проверка приёмки
1. Авторизованный контролёр видит только разрешённые группы, администратор работает по определённой политике доступа; неавторизованный не получает JSON.
2. При отсутствии срока у отдельной задачи весь реестр продолжает загружаться.
3. KPI сверены с контрольной выборкой задач, в том числе несколькими исполнителями и неактуальными.
4. Оба скроллбара работают на узких экранах и с большой таблицей; графики имеют читаемые подписи.
5. Права доступа/ошибки API не прячутся за «пустым графиком».
6. Существующие МЕМО и протокольные дашборды не сломаны; есть rollback.

## Известное состояние на дату записи
API кабинета возвращал 331 уникальное поручение МЕМО; протокольных поручений в этом API ещё нет. Отдельные UI-правки поставлялись архивами v3.5–v3.7, их работоспособность в продакшене требует проверки; код ZIP не полностью опубликован в GitHub.
