# Выбор пилотной группы с контролёрами (24.11.2026)

**Не использовать группы 446 и 734 для приёмки кабинета контролёра**, если в них действительно отсутствуют сотрудники из утверждённого списка контролёров. Техническая диагностика задач группы 446 успешна, но права контролёра и его работа с поручениями не проверены.

Пока **не подтверждён ID списка сотрудников-контролёров**, не угадывать его (в ТЗ от 27.10.2026 он помечен как ожидающий уточнения). Источник должен быть согласован с владельцем процесса и настроенной интеграцией. Не подменять список всеми наблюдателями или всеми членами группы.

## Алгоритм

1. Получить ID контролёров из действующего корпоративного списка; сохранить их локально в памяти оператора, не публиковать в Git, сообщениях, логах и аналитике.
2. Сформировать до 10 групп-кандидатов, относящихся к протоколам или МЕМО, **а не любые группы Битрикс24**.
3. Вызвать `sonet_group.user.get` для каждого ID и найти пересечение участников с IDs контролёров. Метод доступен через REST scope `sonet_group` (корпоративная версия может отличаться). Скрипт `select_pilot_group_v69.py` показывает только количество совпадений и статус чтения. Ошибка доступа = «неизвестно», а не «контролёров нет».
4. По группе с пересечением отдельно проверить задачи с контролёрами в `AUDITORS` и/или комментариями, полномочия конкретного пользователя и наличие разных статусов, сроков и переносов. **Членство в группе само по себе не подтверждает права кабинета**, а код ROLE `A/E/K` – это роль участника группы, не «роль контролёра».
5. Только после этого использовать `probe_cli_v69.py` для ограниченной пагинации задач выбранной группы, не вычисляя ИД из неполных данных.

## Команда для сравнения кандидатов

Скопировать `select_pilot_group_v69.py` из этой ветки в `/tmp`. На сервере:

```bash
cd /webapp/app
read -r -p 'ID профильных групп-кандидатов (через запятую): ' GROUPS
read -r -s -p 'ID контролёров из утверждённого списка (через запятую): ' CONTROLLERS
echo
sudo -u dev env PYTHONPATH=/webapp/app PYTHONDONTWRITEBYTECODE=1 CONTROLLER_PILOT_CONTROLLER_IDS="$CONTROLLERS" \
  python3 -B /tmp/select_pilot_group_v69.py --groups "$GROUPS"
unset CONTROLLERS
```

Скрипт только читает участников, не сохраняет записи и не меняет systemd/SQLite. Не хранить контролёрские IDs в истории shell как текст команды. Не отправлять вывод с идентификаторами сотрудников. При недоступном методе `sonet_group.user.get` выдаётся `status=unavailable`.

Официальная документация: https://apidocs.bitrix24.ru/api-reference/sonet-group/members/sonet-group-user-get.html
