# Пробная сверка списка № 83 и наблюдателей задачи № 77852 (v7.0)

- **Источник:** корпоративный список `https://bitrix.gsprom.ru/services/lists/83/view/0/?list_section_id=` – ссылка предоставлена пользователем. Содержание списка не проверено заранее.
- **Задача:** ID 77852, группа 734 – ранее подтверждена REST-запросом, среди наблюдателей 4 человека.
- **Назначение:** проверить наличие сотрудников, указанных в списке № 83, среди наблюдателей задачи. Наличие совпадения само по себе не подтверждает полномочия пользователя в кабинете.
- **Безопасность:** только REST-чтение. Скрипт не выводит имена, ID сотрудников, тексты задач, токены или необработанные ответы API; SQLite и серверные маршруты не меняются. Не добавляйте этот файл в `main.py`.

Вызовы: `lists.get.iblock.type.id` (подтверждение типа инфоблока), `lists.field.get` (определение полей списка), `tasks.task.get` (только ID, GROUP_ID, AUDITORS), `lists.element.get` (только выбранное свойство сотрудника, постранично – до 500 записей). Для клиента `fast_bitrix24` используется `raw=True`. Требуется право `lists` на чтение списка; при отсутствии прав проверка завершится безопасной ошибкой.

## Запуск с серверного архива

```bash
cd /tmp
unzip controller_list83_v70.zip
bash controller_list83_v70/install.sh
cd /webapp/app
sudo -u dev env PYTHONPATH=/webapp/app PYTHONDONTWRITEBYTECODE=1 \
  python3 -B /tmp/roster_probe_v70.py --list-id 83 --group-id 734 --task-id 77852
```

Если в списке несколько полей типа `S:employee`, скрипт покажет только их ID и названия (метаданные) и сообщит `status: needs_field_selection`. Тогда повторный вызов с `--employee-field PROPERTY_...` (из выведенных полей) позволит избежать неверного выбора.

Если в списке вообще нет поля типа `S:employee`, потребуется проверить структуру списка и возможность однозначно получить **ID пользователей**, а не просто ФИО. Не подменяйте эту проверку сравнением строк ФИО.

Сканирование не более десяти страниц по 50 элементов; при неполной выборке `list_scan_complete=false`, отсутствие совпадения считается неопределённым, а не отрицательным.

Ни одна команда не перезапускает `bitrix-dashboards`, не модифицирует существующие файлы FastAPI, БД истории или архивов. Код и тесты хранятся в ветке `feature/controller-dashboard`, PR #60.
