# Кабинет контролёра · v7.1 – группа № 734 (ручной тестовый срез)

Дата: 24.11.2026. Ветка исходников: `feature/controller-dashboard`, PR #60 в `tarlykov1/Protokoly`.

## Что добавлено

- Серверный диагностический сбор `collect_group734_v71.py` для **одной** заранее определённой группы № 734 и списка сотрудников УПОСиК № 91 (`PROPERTY_306`). REST v2 `tasks.task.list` опрашивается **постранично, по 50 записей**, максимум 20 страниц по умолчанию (до 40 по явному параметру). Новые запросы выполняются **только по команде оператора**, не из браузера и не по расписанию.
- Из задач запрашиваются лишь `ID`, `GROUP_ID`, `STATUS`, `DEADLINE`, `AUDITORS`. Код проверяет соответствие каждой задачи группе № 734 и отсутствие повторов. Текст, название, исполнитель, ФИО, пользовательские ID и история комментариев **не сохраняются в файле сводки**.
- Сотрудники читаются из списка № 91, а не из списка помощников № 83. Совпадение в наблюдателях считается отдельно. При наличии двух **отдельно заданных на сервере** технических логинов через `CONTROLLER_PILOT_TECH_LOGINS` скрипт проверяет их через `user.get` и формирует отдельный счётчик без них. Если настройка отсутствует или проверка не подтверждена, счётчик остаётся `null`, а не выдаёт сомнительную классификацию. Логины не включаем в публичный GitHub.
- Сохраняется **только агрегат** в `data/group734_summary_v71.json` с правами `0600`, через атомарную замену. Существующие `pilot.sqlite` и `pilot_comment_snapshots.sqlite` не меняются. Снимок нельзя считать доказательством прав конкретного контролёра.
- Новая страница `/controller-pilot-test/overview/group734/` с распределением кодов статусов, ближайшими сроками, возможной просрочкой и охватом наблюдателей. Данные отдаются через отдельный **защищённый существующим пилотным Bearer-токеном** маршрут `/controller-pilot-test/overview/group734/data`, только из сохранённого снимка. API не делает прямых запросов в Битрикс24.
- Исполнительская дисциплина, «неактуальные» поручения и недельная динамика намеренно **не рассчитываются** до согласования методики, полномочий и нескольких сопоставимых срезов. Просрочка на экране – индикатор по **текущему** крайнему сроку для статусов, отличных от `5`, а не утверждённый KPI.

## Установка (ZIP вручную)

Перенеси архив `controller_group734_v71_2026-11-24.zip` в `/tmp` сервера `gsprom-app113` и выполни:

```bash
cd /tmp
unzip controller_group734_v71_2026-11-24.zip
bash controller_group734_v71/install.sh
```

Нужна уже работающая v6.7. Установщик проверяет её наличие, делает backup `timeline_v6.py.bak.v7_1_МЕТКА`, **только добавляет четыре маршрута к существующему тестовому роутеру**, устанавливает новые файлы и не затрагивает `main.py`, production-controller и SQLite. `systemd` не перезапускается автоматически.

**Только после согласования общего перезапуска**:

```bash
sudo systemctl restart bitrix-dashboards
sudo systemctl status bitrix-dashboards --no-pager -l
bash /tmp/controller_group734_v71/smoke_test.sh
```

У `smoke_test` ожидается код `200` для страниц и `401` для API без токена.

## Сбор группы № 734 (оператор вручную)

Сначала безопасный проверочный вызов – без записи:

```bash
cd /webapp/app
sudo -u dev env PYTHONPATH=/webapp/app PYTHONDONTWRITEBYTECODE=1 \
python3 -B /webapp/app/controller_dashboard_test/collect_group734_v71.py --max-pages 20
```

Если результат корректен, явно сохрани обезличенный снимок:

```bash
cd /webapp/app
sudo -u dev env PYTHONPATH=/webapp/app PYTHONDONTWRITEBYTECODE=1 \
python3 -B /webapp/app/controller_dashboard_test/collect_group734_v71.py --max-pages 20 --write
```

Открыть в корпоративной сети (доступ только после ввода существующего тестового токена):

`http://gsprom-app113:8000/controller-pilot-test/overview/group734/`

При неполной выгрузке (`pagination_complete=false`) экран **явно показывает частичный охват**. Если число задач больше 1000, после оценки нагрузки можно повторить с `--max-pages 40` (до 2000). Повторная запись перезаписывает только агрегат, не расширяет таблицы пилотной истории.

## Безопасность и ограничения

- В GitHub **не загружаются** корпоративные выгрузки, API-токены, SQLite, имена/ID сотрудников или имена задач. ZIP содержит исключительно код, тесты и инструкции.
- Сервисный REST-доступ **не является** проверкой прав конкретного сотрудника. Публичный доступ к текущему тестовому HTTP/токену необходимо закрыть и перейти на HTTPS с серверной авторизацией до реального предоставления кабинета контролёрам.
- Само наличие пользователя из списка № 91 в `AUDITORS` не подтверждает выполненную контрольную реакцию. Мы не считаем административные комментарии персональной реакцией.
- Нет автоматической синхронизации, нет массовой загрузки комментариев и нет передачи текущих сырых задач в браузер.
- Источник списка № 83 – **помощники**, он намеренно не используется.
- Если настройка `CONTROLLER_PILOT_TECH_LOGINS` отсутствует либо `user.get` не возвращает оба заданных технических логина, `tasks_with_nontechnical_roster_auditor=null`: не выдавать отсутствие данных за нулевой результат.

## Откат

Возьми метку из имени резервной копии после установки:

```bash

```
