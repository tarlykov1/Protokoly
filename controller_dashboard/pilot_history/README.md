# Кабинет контролёра · тестовая сводка и история v6.7

23 ноября 2026. Работает поверх установленной v6.6 (`controller_dashboard_test`). **Только тестовый маршрут.** Не меняет рабочий дашборд, production-API, маршруты БП, `main.py`, `pilot.sqlite` или `pilot_comment_snapshots.sqlite`.

## Что сделано

- Новая страница **`/controller-pilot-test/overview/`** – безопасное тестовое представление реестра поручений из накопленной истории: число задач с историей, событий, изменений срока, сохранённых комментариев, список задач и переход к их хронологии. Данные читаются только из локальной SQLite. Для работы нужен `CONTROLLER_PILOT_TOKEN`, который используется только в запросе и не сохраняется в браузере/URL.
- Данные исполнительской дисциплины, текущая просрочка, недельная динамика исполнения и реальная принадлежность к группам **сознательно помечены как «Не рассчитано»**. По историческим изменениям эти показатели невозможно достоверно восстановить. Для следующего этапа нужен отдельный API состояния задач/групп с проверкой прав и принятой методикой исключения неактуальных поручений.
- В существующей хронологии **первый снимок старого комментария больше не создаёт вторую карточку**, когда уже есть событие `COMMENT`, `COMMENT_EDIT` или `COMMENT_DEL` с тем же ID. Снимок показывается как подтверждённый текст рядом с событием с указанием даты фиксации. Повторные редакции (v2+) и события исчезновения/возврата из API остаются отдельными событиями на дату наблюдения. Источники `legacy` и `chat` не смешиваются.
- Для комментариев с несколькими сохранёнными версиями появилось **сравнение двух последних снимков «Было / Стало»**; это сравнение наблюдений, а не доказательство того, когда именно пользователь редактировал комментарий.
- Переход со сводки к задаче передаёт только `task_id`. Не передаёт токен или текст переписки.

## Для запуска тестового кабинета

Существующий тестовый кабинет уже доступен по адресу `http://gsprom-app113:8000/controller-pilot-test/` согласно предыдущим проверкам. Новая сводка v6.7 располагается по отдельному адресу и не подменяет основной кабинет:

- `http://gsprom-app113:8000/controller-pilot-test/overview/` – новая сводка пилота (v6.7).
- `http://gsprom-app113:8000/controller-pilot-test/timeline/` – история поручения.

Новая страница отображает **факты накопленной истории**, а не все реальные поручения и не реальную ИД.

## Установка

Перенесите ZIP в `/tmp` на `gsprom-app113` и выполните:

```bash
cd /tmp
unzip controller_timeline_v6_7_pilot_2026-11-23.zip
cd controller_timeline_v6_7_pilot
bash install.sh
```

Установка требует наличие v6.6. Копируются только четыре файла тестовой хронологии и четыре новых файла сводки. Установщик делает резервные копии с меткой `Backups stamp`, проверяет синтаксис Python/JS без создания `__pycache__` и не перезапускает сервис. `comment_archive_v66.py` и SQLite не меняются.

После согласования перезапуска **общей** службы:

```bash
sudo systemctl restart bitrix-dashboards
sudo systemctl status bitrix-dashboards --no-pager -l
```

Проверка без токена (не печатает содержимое задач):

```bash
cd /tmp/controller_timeline_v6_7_pilot
bash smoke_test.sh
```

Ожидается `200` у страниц обзора и хронологии и `401` у API без токена. Затем откройте в браузере обзор, введите тестовый токен и нажмите «Загрузить сводку». На задаче № 100193 откройте «Хронология»; 9 сохранённых снимков должны быть по-прежнему доступны. Если 9 архивных снимков связаны с событиями комментариев в истории, общий список хронологии больше не обязан содержать 34 отдельные карточки: повторные первые фиксации будут скрыты именно из общего списка, но сохранены в архиве и БД.

## Откат

```bash
cd /tmp/controller_timeline_v6_7_pilot
bash rollback.sh YYYYMMDD_HHMMSS
```

Замените метку на значение `Backups stamp`, напечатанное установщиком. Скрипт восстанавливает прежние четыре файла и удаляет новые файлы сводки, если их не было до установки. Перезапуск службы – отдельно, в согласованное время. Ни одна SQLite не удаляется.

## Ограничения и безопасность

1. Тестовый контур не обеспечивает автоматически право просмотра всех задач групп: ручной тестовый токен и выборка истории не заменяют модель прав Битрикс24. Перед пилотом для нескольких контролёров нужно добавить серверную авторизацию, разграничение по группам и HTTPS.
2. Автоматическая фоновая синхронизация не включена. Нельзя включать массовый REST-опрос и хранение переписки, пока не утверждены группы, частота, права, нагрузка и политика хранения. v6.7 обновляет сводку по кнопке, читая локальные данные.
3. Индикатор «изменения сроков» считает события переноса, **не** количество просроченных поручений. «Задачи с историей» – не полное число задач. Ничего не «достраивается» фиктивными значениями.
4. Новая сводка не возвращает текст описаний/комментариев, только агрегаты и ID задач. Подробности остаются в защищённом тестовом API истории.
5. До подтверждения источников нельзя считать показатель ИД по формуле `исполненные / актуальные`, поскольку текущие статусы задач не подтверждены. После согласования: завершённость – по главному ответственному, неактуальные исключаем из знаменателя и выводим отдельно, группы и права – из состава групп Битрикс24, сравнение – по одинаковым периодам.

## Локальные тесты

`PYTHONDONTWRITEBYTECODE=1 pytest -q tests/*.py`, `node --test tests/*.cjs`, `node --check` – тестируются агрегаты и запрет на запись, авторизация, HTML/CSS/JS-маршруты, сохранение обеих SQLite, объединение карточек, история редакций, установка и откат. Браузерную проверку с корпоративным сервером выполняем только после установки – локальный браузер здесь ограничен политикой среды.
