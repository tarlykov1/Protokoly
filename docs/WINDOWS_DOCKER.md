# Windows: запуск через Docker Desktop

Нужны Windows с WSL2, Docker Desktop в режиме Linux containers и Git. Приложение слушает только localhost:8000. PostgreSQL не публикует порт наружу. Python и Node на компьютере устанавливать не требуется.

## Первый запуск

В PowerShell:

```powershell
git clone https://github.com/tarlykov1/Protokoly.git
cd Protokoly
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Start-Protokoly.ps1
```

Откройте http://localhost:8000/settings/integrations. Логин `local`; пароль — содержимое `.local/secrets/local_password`. Скрипт генерирует случайные пароли только при их отсутствии. Не удаляйте `.local/secrets`: ключ шифрования нужен для чтения сохранённых подключений.

1. В настройках Битрикс24 выберите REST, включите интеграцию, задайте адрес портала и входящий вебхук. Проверьте соединение. Пустое поле секрета при повторном сохранении оставляет прежнее значение.
2. У вебхука должны быть разрешения на пользователей, группы и задачи. Локальное приложение действует от имени владельца этого вебхука, установленного через `user.current`. Общий пароль локального приложения не предназначен для многопользовательского доступа.
3. Создайте проект с ID его группы Битрикс24. Владелец группы (`A`) и модераторы (`E`) могут менять документы; участники (`K`) могут читать. Запросы и приглашения в группу не дают доступа. Произвольные локальные роли не расширяют права группы. Это консервативное соответствие ролям группы; индивидуальные настройки функций портала не превращаются в дополнительные права приложения.
4. Синхронизируйте сотрудников из Битрикс24. У исполнителей должны быть подтверждённые ID. При нескольких исполнителях выберите главного ответственного в редакторе.
5. Утвердите протокол и запустите публикацию. Её ход виден в «Журнале интеграции». Приложение продолжает частичную публикацию, сохраняя каждую созданную связь. Неизвестный результат создания требует сверки по XML_ID; запрос не повторяется вслепую.

До настройки вебхука страницы проектов возвращают 503: доступ закрыт, пока невозможно проверить права. Настройки интеграции остаются доступны по прямому адресу выше.

## Обновление и резервная копия

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Backup-Protokoly.ps1
git pull --ff-only
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Start-Protokoly.ps1
```

Копия содержит PostgreSQL, файлы документов и секреты. Храните её в защищённой папке: она даёт доступ к подключениям. Обновление запускает миграции до старта web и worker. Именованные тома сохраняются. Команда `docker compose down -v` удаляет данные — для обычной остановки используйте `docker compose stop`.

## Восстановление

Восстанавливайте сначала в отдельную установку. Скопируйте `secrets` из резервной копии в `.local/secrets`, затем:

```powershell
docker compose up -d db
docker compose cp C:\backup\database.dump db:/tmp/restore.dump
docker compose exec -T db pg_restore -U protocols -d protocols --clean --if-exists --exit-on-error /tmp/restore.dump
```

Файлы `files.tar.gz` распакуйте в том `app_data`, сохраняя владельца UID 10001. После восстановления выполните скрипт запуска; он применит недостающие миграции. Не переносите только БД без исходного ключа шифрования.

## Диагностика

```powershell
docker compose ps
docker compose logs --tail=100 web worker migrate
docker compose restart web worker
```

`/health` проверяет процесс, `/ready` — подключение к БД. Уведомление 409 при сохранении означает конфликт версий: сохраните свой текст и обновите страницу. Старые связи с задачами сопоставляются на странице «Сопоставить старые связи» в плане публикации.

Docker-образ использует зависимости из `requirements.lock` с проверкой хешей. Bootstrap и Sortable поставляются локально с лицензиями; браузеру не нужен CDN. Для первой сборки необходим интернет. Сборка и запуск контейнеров проверяются отдельным заданием CI; доступ к реальному порталу Битрикс24 проверяется при настройке на вашем компьютере.
