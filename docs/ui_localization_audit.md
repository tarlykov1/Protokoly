# Аудит русификации пользовательского интерфейса

Проверка пользовательских экранов выявила повторяющийся класс дефектов: технические значения из модели данных (`pending`, `overdue`, `needs_review`, `validation_required`, `in_person`, `memo_protocol` и др.) могли выводиться напрямую в шаблонах, селектах или динамически созданных элементах.

Исправление сделано в двух слоях:

1. Серверный общий UI-компонент содержит единый словарь русских подписей и используется для статусов карточек/поручений.
2. Общий клиентский слой локализует технические значения, которые попали в HTML напрямую или были добавлены динамически JavaScript-кодом. Это также покрывает селекты, импорт, контроль исполнения, публикации, демо и другие экраны.

Основные замены:

- `pending` → «Ожидает выполнения»
- `in_progress` → «В работе»
- `waiting_control` → «Ожидает контроля»
- `completed` → «Выполнено»
- `overdue` → «Просрочено»
- `rejected` → «Возвращено на доработку»
- `needs_review` / `validation_required` → «Требует проверки»
- `in_person` → «Очно»
- `video` → «ВКС»
- `hybrid` → «Смешанный»
- `memo_protocol` → «МЕМО»
- `universal_protocol` → «Протокол»
- `confidence N` → «точность распознавания N»
- `Workflow` → «Этап обработки»

Внутренние значения в базе данных и API не изменяются: русификация касается только пользовательского представления.
